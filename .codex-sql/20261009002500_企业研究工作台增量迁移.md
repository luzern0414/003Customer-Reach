# 企业研究工作台增量迁移

日期：2026-10-09；执行者：Codex。数据库：SQLite；Alembic revision：`20261008_02`，down revision：`20261008_01`。

## 变更范围

新增`companies`、`company_facts`、`procurement_projects`、`procurement_notices`、`company_relations`、`research_companies`六张表；向`jobs`增加`query_mode`、`company_ids`，向`evidence`增加`source_meta`，向`leads`增加可空`company_id`。这是加法迁移，不删除旧表、旧客户、旧证据、旧任务或checkpoint。

## 执行方式

先使用一致性备份，再运行应用初始化（在backend执行 `.venv/Scripts/python.exe -c "from app.db import initialize; initialize()"`，或运行根start.ps1）。项目没有alembic.ini，不能执行裸Alembic命令。本轮备份：`.codex-tmp/architecture-backup-20261008211720/clientreach.db`及`checkpoints.db`；备份时旧库无queued/running/cancelling任务，记录为10 leads、14 conversations、21 jobs、152 evidence。隔离数据库两次初始化均到`20261008_02`，旧记录数量保持，六张新表存在。

## 冻结迁移DDL（原样，按执行顺序）

六表及索引来自revision的DDL列表；ORM的Python默认值不是数据库server default。旧表补列先检查存在性，已有列不重复执行。

```sql
CREATE TABLE companies (
	id VARCHAR NOT NULL, 
	identity_key VARCHAR NOT NULL, 
	name VARCHAR NOT NULL, 
	short_name VARCHAR, 
	entity_kind VARCHAR, 
	view_scope VARCHAR, 
	visibility VARCHAR, 
	credit_code VARCHAR, 
	origin VARCHAR, 
	research_as_of VARCHAR, 
	metadata_json JSON, 
	created_at VARCHAR, 
	updated_at VARCHAR, 
	PRIMARY KEY (id), 
	UNIQUE (identity_key)
);

CREATE INDEX ix_companies_name ON companies (name);

CREATE INDEX ix_companies_visibility ON companies (visibility);

CREATE TABLE company_facts (
	id VARCHAR NOT NULL, 
	unique_key VARCHAR NOT NULL, 
	company_id VARCHAR NOT NULL, 
	category VARCHAR, 
	field VARCHAR NOT NULL,

	unit VARCHAR, 
	raw_unit VARCHAR, 
	report_period VARCHAR, 
	as_of VARCHAR, 
	scope VARCHAR, 
	status VARCHAR, 
	source_ids JSON, 
	quote TEXT, 
	note TEXT, 
	provenance JSON, 
	created_at VARCHAR, 
	updated_at VARCHAR, 
	PRIMARY KEY (id), 
	UNIQUE (unique_key), 
	FOREIGN KEY(company_id) REFERENCES companies (id)
);

CREATE INDEX ix_company_facts_company_id ON company_facts (company_id);

CREATE INDEX ix_company_facts_field ON company_facts (field);

CREATE TABLE procurement_projects (

	created_at VARCHAR,

	PRIMARY KEY (id),

	FOREIGN KEY(buyer_id) REFERENCES companies (id)
);

CREATE INDEX ix_procurement_projects_buyer_id ON procurement_projects (buyer_id);

CREATE INDEX ix_procurement_projects_record_kind ON procurement_projects (record_kind);

CREATE TABLE procurement_notices (
	id VARCHAR NOT NULL, 
	unique_key VARCHAR NOT NULL, 
	project_id VARCHAR NOT NULL, 
	title VARCHAR NOT NULL, 
	notice_type VARCHAR, 
	published_at VARCHAR,

	PRIMARY KEY (id),

	FOREIGN KEY(project_id) REFERENCES procurement_projects (id)

CREATE INDEX ix_procurement_notices_project_id ON procurement_notices (project_id);

CREATE TABLE company_relations (
	id VARCHAR NOT NULL,

	source_ids JSON, 
	quote TEXT,

	created_at VARCHAR, 
	PRIMARY KEY (id), 
	UNIQUE (unique_key), 
	FOREIGN KEY(company_id) REFERENCES companies (id), 
	FOREIGN KEY(counterparty_id) REFERENCES companies (id)
);

CREATE INDEX ix_company_relations_company_id ON company_relations (company_id);

CREATE INDEX ix_company_relations_relation_type ON company_relations (relation_type);

CREATE TABLE research_companies (
	id VARCHAR NOT NULL, 
	unique_key VARCHAR NOT NULL, 
	company_id VARCHAR NOT NULL, 
	conversation_id VARCHAR NOT NULL, 
	job_id VARCHAR, 
	position INTEGER, 
	origin VARCHAR, 
	created_at VARCHAR, 
	PRIMARY KEY (id), 
	UNIQUE (unique_key), 
	FOREIGN KEY(company_id) REFERENCES companies (id), 
	FOREIGN KEY(conversation_id) REFERENCES conversations (id), 
	FOREIGN KEY(job_id) REFERENCES jobs (id)

CREATE INDEX ix_research_companies_company_id ON research_companies (company_id);

CREATE INDEX ix_research_companies_conversation_id ON research_companies (conversation_id);

CREATE INDEX ix_research_companies_job_id ON research_companies (job_id);

ALTER TABLE jobs ADD COLUMN query_mode VARCHAR DEFAULT 'auto';

ALTER TABLE jobs ADD COLUMN company_ids JSON DEFAULT '[]';

ALTER TABLE evidence ADD COLUMN source_meta JSON DEFAULT '{}';

ALTER TABLE leads ADD COLUMN company_id VARCHAR;

CREATE INDEX IF NOT EXISTS ix_leads_company_id ON leads(company_id);
```

## 数据安全与回退

预算、候选报价、成交金额和需求数量分栏保存；未知币种不转换为人民币；重招/候选/结果公告按阶段保存，项目计数去重。历史资料导入使用`dataset_id + source_id`命名空间并校验原文哈希，不能依赖临时目录长期存在。迁移失败或需要回退时恢复上述一致性备份；不执行自动`DROP TABLE`或破坏性降级。
