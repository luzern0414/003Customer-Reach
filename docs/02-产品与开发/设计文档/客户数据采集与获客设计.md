# 客户数据采集与获客设计

## 产品目标

把“输入公司名后补全画像”扩展成可验证的获客闭环：

```text
目标画像 → 候选企业 → 企业去重 → 证据补全 → 联系人核验
        → 可能产品推荐 → 销售准备包 → 通话/拜访 → 需求确认 → 商机
```

系统给销售的不是一堆抓取结果，而是：为什么推荐这家公司、证据是什么、哪些字段还缺、应该问什么、可能匹配哪些产品。

## 信息分层

| 信息 | 可接受证据 | 业务含义 |
| --- | --- | --- |
| 登记经营范围 | 授权工商 API、企业公开登记信息 | 企业登记事实，不等于当前采购需求 |
| 企业主营产品 | 官网产品页、资质/招投标文件、客户确认 | 业务事实，需要来源和时间 |
| 采购品类/数量/价格 | RFQ、通话确认、合同、ERP、合法采购数据 | 高价值事实，必须保留原始证据 |
| 可能需要的产品 | 经营范围、行业、设备、招投标、历史需求组合推断 | 仅为销售推荐，不能写成已确认需求 |
| 联系手机号 | 客户主动提供、授权数据服务、企业公开业务电话 | 个人手机号需合法依据、脱敏、退订和删除 |

## 证据字段

所有关键事实都应保存：`value`、`source_type`、`source_uri_or_locator`、`captured_at`、`effective_at`、`confidence`、`verification_status`、`model_version` 和 `verified_by`。

证据不足时显示“未知/待核验”，禁止由模型补造。

## 销售工作台

1. 销售设置行业、地区、规模、物料品类和排除条件。
2. 系统生成候选企业，先进入待核验队列，不直接进入私海。
3. 线索卡展示来源、时间、证据缺口、评分因子和推荐理由。
4. 系统生成客户准备包：公司摘要、可能产品、开场问题、需要核实的字段。
5. 通话结束后提取型号、数量、预算、交期、决策角色和竞品。
6. 销售确认或驳回关键事实后，才允许生成报价草稿。
7. 销售记录有效、无效、号码失效、已联系、转商机、成交或丢单，反馈回采集和评分规则。

## 试点验收

- 企业去重准确率和关键字段完整率可统计。
- 每条关键事实都能打开来源或证据片段。
- 经营范围标签与实际采购需求分开显示。
- 产品推荐显示匹配理由、证据和置信度。
- 手机号展示来源、授权状态、有效/失效状态和退订状态。
- AI 报价只能保存草稿，库存、成本、税率、MOQ、交期和有效期缺失时不能发送。
