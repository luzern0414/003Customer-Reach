# 12 招投标情报与上下游（v0.4）

日期：2026-10-10。本文说明企业研究中“采购信息、上下游关系、竞争对手、工商摘要、企业标识、研究经验”的实现、数据来源、验收结果与已知限制。

## 1. 要解决的问题

v0.3 的企业研究只靠模型自由规划 Exa 检索，并要求“采购人必须是目标企业”“关系只来自年报”。实测（北京航天广通科技有限公司）：

| 指标 | v0.3 | v0.4 |
|---|---|---|
| 采购公告 | 0 条（回答“未取得采购公告”） | 80–86 条，含物资清单（如真空继电器×30、昆仑变压器油×8 桶） |
| 中标记录 | 1 条 | 22–32 条，另有候选 6 条 |
| 客户 | 0 | 17 家（中国原子能科学研究院 7 次等） |
| 供应商 | 0 | 12 家 |
| 竞争对手 | 不支持 | 8 家（共同竞标） |
| 工商摘要 | 无 | 法定代表人、注册资本、信用代码、行业、地址、经营范围 |
| 模型调用 / tokens | 8 次 / 6.6 万 | 4–6 次 / 2.5–4.6 万 |
| 总耗时 | 236 秒 | 124–202 秒（招投标节点 20–48 秒） |

## 2. 流程

`company_resolve → company_tenders → company_plan → collect … → answer`

`company_tenders`（`backend/app/tender_intel.py`）在模型规划之前执行，只在用户请求了采购/供应商/客户等字段（或未指定字段）时运行：

1. **平台检索（并行）**：复用 `src/tools/acq_query` 的 OpenCLI 适配器——千里马、中国采购与招标网、必联网、乙方宝公开页（免登录）。角色只按适配器原始的采购人/中标人字段与“标题以本企业开头”判定，不再把“结果公告”推断为中标。
2. **全网检索**：Exa 查询 `{企业}招标中标信息 / 招标公告 / 中标 / 中标候选人 成交结果 / 合作单位 供应商`，用于发现：
   - 千里马系企业主页 `…/qiye/{slug}/`（招标公告 `/1/`、中标公告 `/2/`、合作单位 `/4/`、竞争对手 `/5/`、工商信息 `/6/`）；
   - 建设通中标业绩页（`cbi360.net/hhb/sg_*/zb/`）与业主页（`cbi360.net/hhb/proprietor/*`，常合作供应商、历史发包）；
   - 水滴标讯企业页（`biaoxun.shuidi.cn/company-detail/*`，逐条标注“招采单位/中标单位”）；
   - 第三方供应商名录页。
   Exa 受限时，从数据库已保存记录与“企业研究档案”记忆中取回已知主页地址。
3. **读取**：企业主页与原始公告先直接 HTTP 读取（同站≥1 秒间隔、仅公网地址、robots 允许的 `/qiye/` 路径），正文由脚本加载的站点（千里马详情）或直接读取失败时改用 Exa 已索引版本；验证码/登录页不绕过。
4. **追溯原始公告**：企业主页只有标题的“候选人公示/结果公告”，按标题检索原文并读取，取得中选人、候选人名单与项目编号（竞争对手、供应商的来源）。
5. **解析**（`tender_parse.py`、`tender_html.py`，纯函数，有真实页面夹具测试）：标签式（采购人/中标人/确定成交结果单位…）、纵向表格（表头逐行）、Markdown 表格、Exa“: 单元格”块表格、物资清单表；遮挡值（****、点击查看）一律不取。
6. **保存**：`tender_records` 逐条记录（角色、对手方、金额/预算、物资、原文行、证据 ID、置信度 detail/listing/index），`tender_relations` 对手方汇总（客户/供应商/竞争对手/代理，口径 records/platform_stats/third_party_list，次数与最近日期）。同一公告跨平台按“去企业名的标题键”合并，高置信度不被低置信度覆盖。
7. **覆盖判断**：平台已确认的采购/客户/供应商视为对应字段已覆盖，模型只规划官网、联系方式、经营报告等剩余缺口。

## 3. 数据口径（界面与回答一致）

- 次数是公开招投标/平台合作统计次数，**不是年度交易额**；年报披露的金额关系保留在原“上下游关系”中，两者不混算。
- “待核实”记录：平台检索提到企业但未能确认其角色，单独折叠展示，不计入采购或中标数。
- 工商摘要来自招投标平台企业页（多来源时首个优先、其余补空），标注来源链接，不覆盖已核验的企业事实。

## 4. 研究经验与记忆（`search_memory.py`）

任务结束后台执行：

- `search_experience`：按来源（招投标平台、检索渠道、站点域名）累计尝试/成功/被采用次数，规划提示中给出“过往有效来源”和“多次无结果的来源”。
- `company_memory`：企业研究档案（有效入口、招投标主页、角色计数、缺口），下次研究直接复用主页地址。
- `learned_jobs`：同一任务只学习一次。设置 → 记忆与知识中可查看/停用。

## 5. LangSmith 链路

- 根运行名 `Client Reach · {需求}`，标签 `intent:*`、`mode:*`；每类工具独立命名（`工具·公开检索`、`工具·千里马检索`…），招投标各阶段为子链（平台检索、全网检索、企业主页、追溯原始公告）。
- 任务结束写入 feedback：`verified_facts`、`tender_purchases`、`tender_wins`、`tender_details`、`counterparties`、`model_calls`、`elapsed_seconds`、`job_status`，可在 LangSmith 按项目对比质量。
- 输入/输出是否上传由 `config/langsmith.json` 的 `hide_inputs/hide_outputs` 控制（本地开发默认上传，便于调试提示词）。

## 6. 企业标识（`logo_service.py`）

官网来源优先级：已核验官网事实 → 工商摘要中的官网 → 全网检索候选（首页必须出现企业全称/简称，排除工商查询、招标、招聘等平台）。取图顺序 apple-touch-icon → ≥64px 图标 → 页头 logo 图片 → 小图标/favicon；≤400KB，按魔数识别 ico/png。`GET /api/companies/{id}/logo` 带 `CSP: sandbox` 返回，前端 `CompanyAvatar` 加载失败回退首字。

## 8. 已知限制

- Exa 匿名额度有限，密集测试后会返回 429：主页发现与原始公告追溯受影响（已有数据库/记忆回退）。生产环境请配置 `EXA_API_KEY`（见 `config/README.md`）。
- 大型采购单位的结果公告多在付费墙后（中标人遮挡），供应商只能部分取得；按规则不补遮挡值。
- 乙方宝会员、中国政府采购网、剑鱼、全国公共资源交易平台需要已连接 OpenCLI 扩展的 Agent 专用 Edge（`scripts/acq doctor`）；未连接时这些来源不参与，免登录来源照常工作。
- 千里马系企业主页的 slug 无法从企业名可靠构造，只能经检索或记忆发现。

## 9. 工具可靠性与数据复用（v0.4.1）

### 9.1 内置 OpenCLI（`vendor/opencli`）

- 来源 `@jackwener/opencli` 1.8.8（Apache-2.0），修改记录见 `vendor/opencli/NOTICE.md`。依赖安装：`cd vendor/opencli; npm install --omit=dev --ignore-scripts`。
- **插件目录配置**：定制版支持环境变量 `OPENCLI_PLUGIN_DIRS`（多个目录用 `;` 分隔），从项目目录直接加载插件，同名插件优先于 `~/.opencli/plugins`，并自动把插件内的 `@jackwener/opencli` 链接到内置包。`acq_query/opencli.py` 默认设置为 `src/opencli-plugin`；`config/acq_tool.toml` 的 `[opencli].package_dir = "vendor/opencli"`。不再需要 `opencli plugin install`。
- 手动调用示例：`$env:OPENCLI_PLUGIN_DIRS="src/opencli-plugin"; node vendor/opencli/dist/src/main.js qianlima search "企业全称" -f json`。

### 9.2 检索兜底

Exa 限流（429）、失败或无结果时，改用插件命令 `websearch run baidu|sogou`：`tools/browser/search-edge.cjs` 启动临时无头 Edge（常规桌面 UA），经 CDP 让内置 OpenCLI 执行检索，百度为主、被验证或无结果时用搜狗；推广与跳转链接丢弃，结果经 `web_search.WebSearchRow` 校验。招投标检索、通用公开检索（`search_accounts`）与官网发现都使用该兜底。`CLIENTREACH_SEARCH_FALLBACK=false` 可关闭（测试默认关闭）。

### 9.3 网站指引、重试与质量约束

- `backend/app/site_guides.py`：13 个来源的能力、访问方式、最小间隔、重试策略、质量要求与注意事项；设置 → 网站指引展示同一份数据（`GET /api/site-guides`），并写入规划/补查提示。
- 重试：只重试临时错误（超时、5xx、检索失败、空正文），验证码/登录/限流/404/输出不合格不重试；次数与退避按站点策略。
- 结构化输出：工具输出经 `tender_models` 的 `PlatformSearchOutput / WebSearchOutput / PageReadOutput` 校验，不合格记为 `bad_tool_output`；保存前记录与对手方经 `TenderRecordProposal / TenderRelationProposal` 校验（遮挡名称、非法日期、非 http 地址拒绝并计数）。
- 噪声控制：平台全文检索命中但标题/摘要未出现企业全称的公告不保存；Exa 限流后跳过只能经 Exa 读取的站点。

### 9.4 复用已保存数据

- 节点级：企业在“招投标数据复用时长”（设置，默认 24 小时）内采集过且有已确认记录、用户未要求“最新/刷新/重新”时，直接复用数据库记录，不访问站点。
- 调用级：其他任务近期（复用时长内）相同参数的检索与页面读取结果直接复用，并标明来源任务。
- 研究摘要：`tender_service.research_summary()` 生成 `CompanyResearchSummary`（Pydantic），作为回答模型的输入并写入最终数据集，后续任务可直接读取。

## 10. 集团自建采购平台（接入 BidMonitor-AI 清单，2026-10-10）

- **评测结论**：开源项目 [BidMonitor-AI](https://github.com/zhiqianzheng/BidMonitor-AI)（v1.7，2025-12-19，仓库无 LICENSE 文件、README 自称 MIT）的 9 个 requests 爬虫以企业名或行业词检索，7 个返回 0 条、2 个只返回首页通用列表（无关键词过滤），对企业研究无增益；其 Selenium 模式把首页全部链接记为“当天公告”，日期不可信，且使用随机 UA 轮换，与本项目合规原则不符。**因此不复制其代码，只引用其整理的 45 个央企/大型企业采购平台网址清单。**
- **实测可读性**（直接读取 + 内置 OpenCLI 浏览器渲染）：国家电网（浏览器，首页 20 条带日期公告）、中国能建（直接读取，13 条）、江苏交控（浏览器）可用；南方电网、中国电建、三峡、国家电投、隆基等需登录；中国电力招标网、国电投招标网有滑动验证；中国建材、Ariba 的 robots 禁止全部；华能、华电、国投、中交等连接失败或被拒；国家能源、大唐、五矿首页无公告列表。
- **接入方式**：`backend/app/procurement_portals.py` 登记 26 个平台及集团关键词与实测状态；研究企业名称命中集团关键词（如“国网”）且平台为 available 时，`TenderCollector.read_group_portal` 读取首页公告，标题含企业全称（或去“有限公司”后名称）的记为采购记录（官方源头，标注平台名）。
- **实测**：国网江苏省电力有限公司——国家电网平台浏览器读取 19 秒，确认 2 条本单位采购公告（框架协议公开招标）；合计采购记录 25 条。
