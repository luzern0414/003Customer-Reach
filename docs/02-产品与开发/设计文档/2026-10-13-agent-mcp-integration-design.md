# Agent MCP 统一检索与证据设计

用户授权：在当前项目直接接入企查查凭据及 `bidresearch.mcp_server`，优化现有 Agent，验收软件 / AI 服务信息。

## 选择与边界

沿用 LangGraph + ToolBroker + SQLite checkpoint。选择在现有编排中增加两个有界适配器，而不是建立第二套 Agent 或把外部代码整体复制进项目。原公开搜索仍负责官网、年报及未覆盖来源；MCP 负责工商结构化信息和采购公告。

保留普通聊天、文件问答、仅给定网页范围、来源关闭、字段引用和暂停恢复契约。凭据只读，认证信息不进入日志、SSE、证据或 Git。测试、真实验收使用独立 UUID 数据库。不会在此任务中重启生产服务或推送仓库。

## 数据流

任务要求 → 能力/范围选择 → ToolBroker 原子额度预留 → 官方 MCP 客户端 → 规范工具结果 → 原始 Evidence → 字段核验/保守去重 → Company/Tender 数据及答案。

共享的 MCP 账本负责同任务成功/失败复用、跨任务隔离、并发防重、暂停和耗时。企查查服务端工具名由已验证只读绑定选择；模型不能任意选择工具、端点或参数名。一次业务调用仅执行一次 initialize/tools/list/call。

BidResearch 启动固定的 `.venv-runtime/Scripts/python.exe -X utf8 -m bidresearch.mcp_server`，cwd 为 `D:/Codes/000GithubProject/Result/001_bid_research_tool`。模型不能提交命令、输出路径或缓存路径。默认 HTTP 来源，REA 浏览器来源显式启用才使用；浏览器缺依赖/访问受限保留状态，不切换读取器绕过。输出留外部工具 data 下，全文带 hash 与来源元数据归档到本任务。

## 信息质量与效率

明确软件 / AI 服务画像时，工具归档与保存入口均要求实际服务需求。泛称平台建设、机构AI名称、纯硬件、资产处置及投标软件说明不能充当服务采购证明。“正在采购”还必须由原文正式提交期限、买方与开放状态共同证明；保证金/报名/文件获取期限、暂停/成交与未知日期不占名额。

标准采购人信息块走小型原文解析器，保留项目编号、预算口径、买方电话及期限，不用模型重写。解析结果仍经原持久门禁。不同公告的采购摘要可并存，保持各自来源及信号，实际身份字段冲突仍保留争议。金额逐字段或表格列验证，候选报价不能成为成交金额。完整结果和降级答复都保留每条原始链接。

企查查按真实 `searchKey` 参数映射，中文字段路径逐级解析，路径值必须与引文一致。完整企业名精确匹配才能自动确认；简称候选不得自动合并。未知/遮挡、统计期或联系归属不足的值不写事实。

采购查询单个主题、少量来源、少量详情；请求、页数、详情、输出、总时长均有上限。日期窗口只按原发布日期过滤，未知日期注明未知。摘要与正文分开；采购人、代理、中标与候选角色分开。相同 URL/正文归档复用，不凭相似标题合并不同阶段、标包或年份。公开网页正文进入原有企业校验，不把检索命中当已确认采购。

## 验收

测试包含实际 stdio 握手、严格 schema、路径/值不符拒绝、调用失败/暂停/并发/跨 Job 隔离、来源关闭与零预算、列表与全文区分及同任务不重检索。真实验收给软件 / AI 需求，检查具体公告原文、机构、金额/日期/引文、重复与缺口；不会以空结果或 partial 声称全站覆盖。
