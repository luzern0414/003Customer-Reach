# 06 前端设计

## 1. 页面与路由（Next.js App Router）

| 路由 | 页面 | 主要组件 |
|---|---|---|
| `/` | **对话工作台**（核心页面） | 左侧：会话列表<br>中间：对话流（assistant-ui Thread）<br>右侧：上下文面板（当前企业画像 / 关系图 / 线索篮），可折叠 |
| `/leads` | 线索库 | 表格（筛选、批量操作、导出 Excel）、状态看板 |
| `/companies/[id]` | 企业详情 | 画像卡、采购历史时间线、中标历史、关系图（G6）、风险、来源列表 |
| `/tenders` | 招采检索 | 结构化检索表单，不经过对话；结果表；详情抽屉 |
| `/graph` | 关系图探索 | G6 大图：搜索企业、展开 N 跳、按关系类型过滤 |
| `/settings` | 设置 | 数据源状态（source_health）、额度与费用、我方产品词表、模型选择、登录态检查（OpenCLI whoami） |

## 2. 对话工作台交互

```
┌ 会话列表 ┐┌──────────── 对话 ────────────────┐┌── 上下文面板 ──┐
│ + 新对话 ││ 用户: 北京近30天采购防火墙的单位… ││ [画像][关系][篮]│
│ 历史会话 ││ ▸ 计划: ①招采检索 ②画像×5 ③关系   ││  企业画像卡     │
│          ││ ▸ 🔧 tender_search  ccgp✓ 乙方宝✓ ││  G6 关系图       │
│          ││      企查查⏭(待确认) 32条/4.1s    ││                  │
│          ││ ┌ 确认消耗: 企查查 5×2元 + … ┐   ││                  │
│          ││ │ [确认] [仅免费源] [取消]    │   ││                  │
│          ││ └────────────────────────────┘   ││                  │
│          ││ [采购公告表格卡] [画像卡×5]        ││                  │
│          ││ 回答正文（带来源角标 [1][2]）      ││                  │
│          ││ [收藏为线索] [导出] [继续追问…]    ││                  │
└──────────┘└───────────────────────────────────┘└──────────────────┘
```

- **工具调用过程可视化**：每个工具调用显示为一行可展开的步骤，内容包括数据源图标、状态（运行中 / 成功 / 失败 / 缓存命中 / 待确认）、条数、耗时、费用。
- **来源角标**：回答中的数字和事实带有 `[n]` 角标，悬停显示来源 URL 和原文片段。
- **HITL 卡片**：对应 `cost_confirm`、`entity_pick`、`browser_action`（请在 Agent 浏览器中登录或确认）三种 interrupt，前端渲染成确认卡片，用户点击后 resume 运行。
- 运行中可以随时**中断**（取消 run）。

## 3. 生成式 UI（Tool UI 注册表）

工具结果的 `type` 与前端组件一一对应：

| type | 组件 | 说明 |
|---|---|---|
| `tender_list` | `<TenderTable>` | 标题、类型、地区、金额、日期、采购人、来源；可排序，可加入线索 |
| `tender_detail` | `<TenderCard>` | 物资明细表、联系人（默认打码，点击查看需二次确认）、原文链接 |

## 4. 技术要点

- **数据流**：
  - assistant-ui 的 `useLangGraphRuntime` 直接对接后端，后端兼容 LangGraph SDK 协议。也可以走 FastAPI 自建的 SSE。
  - 方案 A：后端用 `langgraph-api` 或 LangGraph Server 自托管协议，前端用 `@langchain/langgraph-sdk`。
  - 方案 B：FastAPI 自己实现 `/runs/stream` SSE，前端写一个 runtime adapter。
  - **MVP 选方案 B**，避免依赖 LangGraph Platform 授权。
- **状态管理**：服务端数据用 TanStack Query；轻量本地状态用 Zustand。
- **样式**：shadcn/ui + Tailwind 4。中文排版优先，正文 14px，表格紧凑。支持暗色模式。
- **图组件**：G6 5 采用 `dagre` 布局，节点按类型着色：本企业、采购方、中标方 / 供应商、股东、子公司。支持点击展开，以及右键"查看画像"或"加入线索"。
- **安全**：前端不持有任何第三方密钥。联系人完整号码通过单独接口获取，并写入审计日志。
- **国际化**：仅中文。
