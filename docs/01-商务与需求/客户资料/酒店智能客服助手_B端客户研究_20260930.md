# 酒店智能客服助手：B 端客户研究

日期：2026-09-30（Asia/Shanghai）  
执行者：Codex  
范围：中国酒店运营集团的公开资料小样本；7 家可核验企业/集团候选，另有受限站点候选不进入可联系名单。

## 结论

首个试点优先验证明宇商旅旗下一个品牌或区域；首旅如家、东呈有较明确的集团采购渠道，可进行准入核查；亚朵、华住、锦江适合长期战略线索。德胧/开元已经公开推出高度重叠的自研 AI 产品，不应仅因规模大就列为容易成交的客户。

本报告只证明这些企业与产品场景具有适配信号，不证明它们正在采购、愿意付费或没有现有客服系统。没有发送消息、拨打电话、提交供应商表单、登录企业平台或获取个人手机号。

## 产品假设与目标客户

本例按“官网/小程序的酒店政策与会员问答、预订前咨询、住客服务请求转人工或工单、集团/门店知识库”理解智能客服助手。语音线路、PMS 交易写入、真实预订、退款和会员账户操作不属于本轮验证范围。

最有价值的采购方是酒店运营集团、酒店管理公司、独立经营品牌/区域事业部以及多店业主。前台、数字化/IT、会员运营或客服管理部门是可能的业务参与方，其真实负责人和采购权必须另行确认。加盟开发邮箱、宾客预订电话和投资者邮箱不能直接当作软件采购联系人。

建议优先寻找有自有预订渠道、会员制度、多门店规则和重复 FAQ，同时尚无充分证据表明已自研完整同类系统的客户。20–300 家在营门店是后续试点筛选建议，不是下面企业的已验证规模。

- [酒店业主](https://www.minyounhotels.com/?c=owner)展示委托管理、第三方管理、资产管理及特许经营等模式；该页部分较旧规模口径与新概览不同，不混用。
- [创新发展](https://www.minyounhotels.com/?c=about&a=creative)明确中央预订系统 CRS、客户呼叫中心和全球分销系统 GDS。
- [会员 FAQ](https://www.minyounhotels.com/?c=about_myh&a=question)包含会籍资格、积分、密码找回、会员卡、免费住宿和升级权益等重复问答。规则在不同品牌间存在差异。

### 可核验的公开联系入口

### 推荐理由与验证问题

待确认：近30天咨询量、夜间/峰值人工缺口、现有 AI 系统、预算、CRS/PMS 接口权限以及可自主决策的品牌/区域。官网有这些场景不等于客服负担已经量化。

## 推荐顺序与销售下一步

| 分组 | 企业 | 当前证据支持的动作 |
| --- | --- | --- |
| 单品牌/区域试点优先 | 明宇商旅 | 使用正式商务渠道确认数字化/客服承接人，核验 FAQ/会员客服痛点 |
| 有公开供应商渠道 | 首旅如家、东呈 | 先核查是否接纳软件供应商及既有客服系统，再确定试点 |
| 适配但采购入口未确认 | 亚朵 | 通过官网总机/合作分类确认负责部门，不群发到差旅/媒体邮箱 |
| 长期战略账户 | 锦江、华住 | 先确认品牌/区域决策权限和技术采购入口 |
| 同类产品已存在 | 德胧/开元 | 降级，除非有明确差异化集成价值 |

销售首轮应核验：咨询量、主要问题、夜间/峰值缺口、现有系统、可用知识文档、预算、决策人、PMS/CRS 接口及可独立试点的门店。公开联系方式不等于营销许可，未设置自动触达。

## 工具与证据方法

先由三个独立只读任务核查官方网页、公司/品牌页面和公开页面资源，再用 Exa MCP 搜索/读取及 Playwright MCP 页面快照复核重点结论。搜索摘要不直接充当工商或采购需求事实。

原始 MCP 调用结果保存在 `.codex-tmp/mcp-tests/`；结构化研究候选保存在 `data/normalized/hotel-b2b-research-20260930.json`。它们是研究/待核验数据，不是已合格商机或可以自动群呼的联系人库。

统一社会信用代码、法人、精确登记经营范围、营收、采购预算和手机号没有可用授权工商源时保持未知，禁止补造。正式扩量前须完成来源条款、字段用途、保留期限及数据授权审核。
