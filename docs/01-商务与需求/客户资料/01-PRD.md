# 01 产品需求文档（PRD）—— AI 获客系统

> 版本 v0.1（草案，待评审）· 2026-10-08

## 1. 背景与目标

B2B 销售找客户时，信息分散在很多地方：

- 工商信息：企查查、天眼查
- 货源与供应商：1688
- 招投标：政府采购网、公共资源交易平台、各类标讯聚合站
- 集团集采：央企、国企的电子采购平台

销售要在多个网站之间手工检索、复制、比对，效率很低，也很难看清"谁在买什么、跟谁买、能不能成为我的客户"。

**目标**：用户用自然语言和 Agent 对话。Agent 自动规划并调用工具，从多源数据中找出**正在采购的企业**，并输出：

1. **采购信息**：采购项目、品目、预算/中标金额、时间、阶段（意向 → 招标 → 中标 → 合同）、原文链接。
2. **客户画像**：工商基本面、规模、资质、采购偏好（品类、频次、偏好品牌）、近期采购信号（招聘、融资、扩产）、风险。
3. **上下游关系**：股权关系、集团关系、招标方 ↔ 中标方、供应商 ↔ 客户，以图谱形式展示。
4. **行动建议**：线索评分、切入点、建议对接的部门或角色。只列出合规获取的公开联系方式。

## 2. 用户与场景

| 角色 | 典型问题 |
|---|---|
| 销售 / BD | "帮我找北京地区最近 30 天采购防火墙、预算 50 万以上的单位" |
| 销售 / BD | "北京航天广通科技有限公司最近在采购什么？以前从谁那里买？" |
| 渠道 / 供应链 | "我们做天线罩，谁在持续招标采购天线罩？他们的中标方是谁？（竞品）" |
| 采购方视角 | "在 1688 上找做 RFSOC 板卡的源头工厂，并给出工商背景" |
| 管理者 | "本月新增高意向线索有哪些？按行业和地区汇总" |

## 3. 功能范围

### 3.1 MVP（P0）

| 模块 | 功能 |
|---|---|
| 对话 Agent | 多轮对话；流式输出；**展示工具调用过程**（调用了哪个源、耗时、命中条数）；可中断；支持追问 |
| 招采检索 | 关键词、地区、时间、金额、公告类型多条件检索。数据源：ccgp、乙方宝/千里马、剑鱼、企查查招投标 API、Exa/博查网搜 |
| 企业画像 | 企业名 → 工商信息 + 采购历史 + 中标历史 + 风险 + 采购信号 → 画像卡片 |
| 上下游关系 | 股东 / 对外投资 / 集团；招标方 ↔ 中标方；以 G6 关系图展示 |
| 1688 供应商发现 | 品类关键词 → 商品与店铺 → 关联工商主体 |
| 线索库 | 把对话中发现的企业或项目一键收藏为线索；支持标签、状态、备注；导出 Excel |
| 额度管控 | 付费 API 和会员详情等消耗额度的调用，需要用户确认（HITL）；结果缓存；记账 |
| 来源可追溯 | 每个字段都带 `source`、`source_url`、`fetched_at`；LLM 抽取的字段要能对回原文 |

### 3.2 二期（P1）

- **订阅监控**：关键词、地区、目标企业有新公告时，推送到站内、企业微信、钉钉或邮件。
- **线索评分模型**：规则 + LLM，后续可接入反馈学习。
- **产业链图谱**：引入 Neo4j，支持多跳查询，如"共同供应商""竞品的客户"。
- **报告导出**：客户尽调报告（PDF / Word）。
- **团队协作**：多用户、多租户、线索分配。

### 3.3 不做（明确排除）

- 自动外呼或群发营销：P0 只输出建议，不执行触达。
- 转售原始数据。

## 4. 关键用户流程

```
用户："帮我找北京最近30天采购防火墙的单位，给出画像和他们以前的供应商"
 └─ Agent 规划
     ├─ 1. tender_search(kw=防火墙, region=北京, days=30)   → 并行查多个源 → 合并去重
     ├─ 2. 对 Top N 采购单位：company_resolve → 拿到统一社会信用代码
     ├─ 3. company_profile + tender_history(buyer) + win_history  ← 付费调用前请用户确认
     ├─ 4. relation_graph(buyer)：股权/集团 + 历史中标方 = 供应商
     └─ 5. 汇总：采购列表卡片 + 画像卡 + 关系图 + 线索评分 + 建议
用户：点击"收藏为线索" / "查看联系人（消耗 1 次会员额度）"
```

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 首 token 延迟 | 3 秒以内 |
| 典型多源检索完成时间 | 60 秒以内，过程中流式展示进度 |
| 可靠性 | 单个数据源失败不影响整体结果，并标注"该源不可用" |
| 成本 | 一条线索标准画像的付费 API 成本不超过 8 元；同一企业缓存 7–30 天 |
| 合规 | 见 `08-compliance-security.md` |
| 可观测 | 每次工具调用都记录 trace：输入、输出摘要、耗时、成本 |
| 部署 | 单机（Windows/Linux）可运行；生产环境部署在大陆云主机，需大陆 IP |

## 6. 成功指标（MVP）

- 对 20 个标准问题的评测集：采购信息召回率 ≥ 80%，关键字段（采购人、金额、时间）准确率 ≥ 95%。
- 单条企业画像生成时间不超过 45 秒。
- 销售试用：每人每天至少收藏 5 条线索。

## 7. 待确认事项（需要你决定）

1. **数据源采购**：企查查开放平台/MCP 充值金额；是否购买乙方宝黄金会员（¥398/年，每天 30 条详情）或剑鱼、千里马的数据 API；1688 开放平台是否用企业主体认证。
2. **主力 LLM**：DeepSeek / Qwen / Kimi / GLM / Claude 中选哪个；是否需要私有化部署。
3. **部署形态**：只在本机单用户使用，还是团队 SaaS（决定是否在 MVP 阶段就做多租户）。
4. **目标行业**：优先服务哪些行业（例如网络安全设备、军工配套、家具），这会决定种子关键词和评分规则。
